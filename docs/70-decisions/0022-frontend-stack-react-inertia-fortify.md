## Context

`10-architecture/overview.md` originally assumed the frontend would be **Blade + an undecided admin template**, explicitly "no SPA", with **Laravel Breeze** for auth. That was a placeholder written before the build started.

The application was actually scaffolded on the **Laravel React starter kit**, themed with **"Paces"/"Minute"** (Coderthemes, ThemeForest): React 19 + Inertia 2 + TypeScript + Vite 7 + Tailwind v4, with **Laravel Fortify** providing headless authentication. The same theme/library is used by the sibling app (`mintra.site`), and a large prebuilt page/component catalog comes with it.

We need to record the actual stack and why it diverged from the original placeholder.

## Decision

The authenticated **app surfaces** (back office, and qcminute time-tracking) are built with:

- **React 19 + Inertia 2 + TypeScript**, bundled by **Vite 7**
- **Tailwind CSS v4**, on the **Paces/Minute** theme (reused as a component/page library — see the team's reuse principle)
- **Laravel Fortify** for headless auth: login, password reset, 2FA scaffolding
- **Laravel Sanctum** added later, scoped only to the `/device/*` tablet token path

Inertia gives a **server-driven SPA** — server controllers return page props; there is **no separate API layer**. Typed routes/actions are generated by **Wayfinder**.

The **marketing surface uses Blade**, not React — that is recorded separately in **ADR-0023**.

## Consequences

### Positive

- Rich, interactive UIs (live grids, wizards) without hand-rolling a client/server API
- One server-driven model (Inertia) — controllers stay the source of truth; no API contract to maintain
- A large prebuilt component/page library to adapt, reducing UI build time
- End-to-end type safety (TypeScript + Wayfinder-generated routes)

### Negative

- React/Inertia learning curve vs. plain Blade
- Authenticated pages are client-rendered; anything needing SEO must not live behind Inertia (mitigated — SEO content is the Blade marketing surface, and authenticated pages are gated anyway)
- An optional SSR build exists but adds a process if we ever enable it

### Implementation requirements

- Vite **multi-entry** (one bundle per surface); `@`-alias → `resources/js/admin`
- Wayfinder generates typed routes/actions under `resources/js/admin/{actions,routes,wayfinder}` (gitignored)
- Optional Inertia SSR via `resources/js/admin/ssr.tsx`

## Alternatives considered

### A. Blade + Livewire (the original placeholder direction)

Rejected. The chosen theme and its component catalog are React; rebuilding them in Blade/Livewire would discard that library. Reserved Blade for the marketing surface where it's the better tool.

### B. Vue SPA

Rejected. Legacy QC Minute was Vue, but the theme/library is React and the team standardized on React for the rebuild.

### C. Laravel Breeze

Rejected in favor of Fortify — headless, pairs cleanly with Inertia, and includes 2FA scaffolding out of the box.
